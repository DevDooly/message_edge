# Notification Edge 서명키 교체 실행서

## 1. 목적과 현재 상태

현재 소스와 CI에는 키스토어 및 비밀번호가 포함되지 않는다. 다만 과거 공개 Git 기록에 기존 릴리스 키가 포함되었으므로, 이 키는 더 이상 비밀이라고 간주할 수 없다.

서명키 변경은 기존 설치본의 업데이트 가능 여부에 직접 영향을 준다. 따라서 이 문서는 키를 자동 교체하지 않고, 배포 채널과 지원 기기 조건을 확인한 뒤 안전하게 전환하기 위한 승인 절차를 정의한다.

## 2. 자동 진행 금지 조건

다음 중 하나라도 확인되지 않으면 키 교체와 Git 이력 강제 재작성을 진행하지 않는다.

- 기존 APK 설치 사용자가 새 APK를 데이터 유지 상태로 업데이트할 수 있는가
- Google Play App Signing 사용 여부와 현재 키의 역할이 확인되었는가
- Android 8.0·8.1(API 26·27) 지원 정책이 확정되었는가
- 기존 패키지명 `com.devdooly.notificationedge`를 유지할지 결정되었는가
- 원격 `main` 강제 갱신과 모든 협업자 재클론 일정이 합의되었는가

## 3. 전환 방식 결정

### 방식 A: 기존 설치 호환성 우선

- 기존 서명키를 오프라인 비밀 저장소와 CI Secrets에서만 제한적으로 사용한다.
- 저장소 최신 상태와 빌드 로그에는 키·비밀번호를 남기지 않는다.
- 인증서 지문 고정, APK SHA-256 게시, 업데이트 앱의 패키지·버전·서명 검증을 유지한다.
- 공개된 키 자체의 위험은 해소되지 않으므로 임시 운영 방식으로 취급한다.

### 방식 B: 새 키와 새 패키지로 완전 전환

- 새 애플리케이션 ID와 새 서명키를 사용한다.
- 기존 앱과 별도 설치되며 설정과 알림 접근 권한을 다시 구성해야 한다.
- 기존 사용자를 새 앱으로 안내하는 마지막 공지 릴리스를 기존 키로 배포한다.
- 전환 완료 후 기존 업데이트 채널을 읽기 전용 또는 종료 상태로 바꾼다.

### 방식 C: 배포 플랫폼의 공식 키 교체 절차 사용

- Google Play 등 실제 배포 플랫폼의 키 업그레이드·업로드 키 재설정 절차를 따른다.
- 플랫폼이 제공하는 기기별 호환성 범위를 확인하고 API 26·27 업데이트 시험을 별도로 수행한다.
- 플랫폼 콘솔의 승인 완료 전에는 CI의 인증서 기준값을 변경하지 않는다.

## 4. 실행 체크리스트

### 4.1 전환 전 증거 보존

- [ ] 현재 정상 릴리스 APK와 SHA-256을 오프라인 보관한다.
- [ ] 현재 인증서 SHA-256 지문을 비밀 관리 시스템에 기록한다.
- [ ] 기존 설치본의 버전 코드와 배포 채널별 설치 수를 기록한다.
- [ ] API 26·27·31·34·35의 업데이트 설치 결과를 기록한다.
- [ ] 설정 DataStore, 알림 접근 권한, 오버레이 권한 유지 여부를 기록한다.

### 4.2 새 키 생성과 보관

- [ ] 네트워크와 분리된 환경에서 새 릴리스 키를 생성한다.
- [ ] 키스토어 원본과 복구 사본을 서로 다른 암호화 저장소에 보관한다.
- [ ] 키스토어 비밀번호와 키 비밀번호를 키스토어 파일과 분리한다.
- [ ] GitHub Secrets에 새 키스토어 Base64와 비밀번호를 등록한다.
- [ ] `RELEASE_CERT_SHA256`을 새 인증서 값으로 갱신한다.

### 4.3 전환 후보 검증

- [ ] `testDebugUnitTest`, `compileDebugKotlin`, `lintRelease`, `assembleRelease`가 통과한다.
- [ ] `apksigner verify --verbose --print-certs` 결과가 승인된 새 지문과 일치한다.
- [ ] 기존 설치본 위에 후보 APK를 설치해 업데이트 성공 여부를 확인한다.
- [ ] 신규 설치, 앱 재시작, 재부팅 복구, 알림 수신, 빠른 답장을 확인한다.
- [ ] 실패 시 기존 CI Secrets와 배포 자산을 변경하지 않고 전환을 중단한다.

### 4.4 공개 Git 이력 정리

- [ ] 새 키 전환과 사용자 호환성 검증이 완료된 뒤 별도 유지보수 창을 잡는다.
- [ ] 원격 저장소 보호 규칙과 열린 PR·포크·배포 자동화를 확인한다.
- [ ] 민감 파일을 모든 참조에서 제거한 새 이력을 만든다.
- [ ] 강제 푸시 후 모든 태그와 기본 브랜치를 다시 검증한다.
- [ ] 기존 클론과 포크에는 비밀이 계속 남을 수 있음을 보안 기록에 명시한다.
- [ ] 협업자에게 기존 클론 폐기와 재클론 절차를 안내한다.

## 5. 완료 기준

- 승인된 새 키로 서명된 후보가 지원 대상 기기의 설치·업데이트 정책을 만족한다.
- CI에 승인된 인증서 지문 하나만 남고 키 원문은 저장소와 로그에 없다.
- 기존 키의 보관·폐기 상태와 Git 이력 정리 결과가 감사 가능한 문서로 남는다.
- 사용자에게 재설치, 데이터 초기화, 권한 재승인이 필요한지 릴리스 노트에 명확히 안내한다.
